# ADR-001: 前端整站重写，技术栈改为 Vue 3.5 + Element Plus 2.9

## Status
Accepted (2026-05-21)

## Context（背景）
`inspection-system`（白云机场 T3 GTC 运维资产管理系统）现有前端为 React 19 + Vite 6 + Tailwind v3 + shadcn/Radix（~85 文件），而后端 FastAPI（`/ops/api`）为**不可动红线**。用户核心痛点有二：
1. **低有效视口下元素被拉伸压扁**（1920×1080 + 125%/150% 缩放 → CSS 视口仅 1536×864 / 1280×720）。已定位根因：SVG 同时写死 `width`/`height` 像素属性却只约束宽（`RelationGraph.tsx:134-140`），与正确写法（`DeviceRelationGraph.tsx:42` 的 `viewBox` 自适应）混用、无统一规范。
2. 用户要求本系统技术栈与其既有项目 `tools-management/vue-frontend`（Vue 3.5 + Element Plus 2.9 + vue-router 4.5 + Pinia 2.2 + Vite 5.4）**统一**。

约束：后端与部署链路（nginx `location /ops/` → 9527、后端托管 `<项目>/dist`）不得改动；必须能秒级回滚。

## Decision（决策）
1. **前端整站重写为 Vue3 独立 SPA**（选型矩阵方案 A），构建到 `<项目>/dist`，与 React 产物并存、符号链接切换回滚。
2. **技术栈精确对齐 `vue-frontend`**：`vue ^3.5.0`、`vue-router ^4.5.0`、`pinia ^2.2.0`、`element-plus ^2.9.0`、`@element-plus/icons-vue ^2.3.0`、`axios ^1.7.0`、`vite ^5.4.0`、`@vitejs/plugin-vue ^5.2.0`、`typescript ^5.9.3`、`vue-tsc ^2.2.12`（各范围 npm 现解析真实版本：vue 3.5.42 / element-plus 2.14.5 / icons 2.3.2）。**图表**在 `recharts` 不便迁移处改 `echarts ^6.1.0`+`vue-echarts ^8.3.0`（ADR-002 待立）。
3. **图标库锁 `@element-plus/icons-vue@2.3.2`**（全项目唯一，禁 emoji/二套库）；与 `UIUX.md` §4 / `design-tokens.json` 三方一致。DB `subsystems.icon` 存 lucide 名，前端走 `SUBSYSTEM_ICON_MAP` 映射到 EP 图标（后端不可改）。
4. **响应式硬规则**（见 `ARCHITECTURE.md` §4）：按 CSS 视口设计、基准 1280×720；SVG 禁双像素属性、用 `viewBox+preserveAspectRatio`；Flex/Grid 子项 `min-width:0`；`el-table` 列用 `min-width` + 局部横滚；不改根字号缩放。
5. 回滚：`ln -sfn releases/react-<sha> dist`。

**关联决策（同文件编号）**
- **ADR-001.a 图标库**：Decision = 锁 `@element-plus/icons-vue@2.3.2`；理由 = 与 Element Plus 同源、与 `vue-frontend` 一致、与 `UIUX.md`/`design-tokens.json` 三方对齐；EP 图标无 `stroke-width`，一致性靠 `size`+`currentColor`；Consequences = DB `subsystems.icon` 存 lucide 名，需前端 `SUBSYSTEM_ICON_MAP` 映射（不改后端），EP 缺"消防/火焰"语义图标需按同网格自补 `IconFlame.vue`。备查：`lucide-vue-next` 已 npm 废弃，若未来改用 lucide 须用 `@lucide/vue`（当前不采用）。
- **ADR-001.b 响应式策略**：Decision = 以 CSS 视口为准、基准 1280×720、禁用根字号整体缩放；理由 = 系统缩放导致物理分辨率不可信，Element Plus 尺寸基于 px 变量不随根字号缩放；Consequences = 需立 `ResponsiveSvg.vue` 与 lint 检查锚点。

## Consequences（后果）
**正面**
- 技术栈与用户既有工程**完全统一**，团队熟悉度高、无跨栈心智负担。
- 单产物、一次切换，接口契约（`/ops/api`、Bearer、422 detail 数组拼消息）不变，回归面可控。
- 符号链接切换实现**秒级回滚**，发布风险低。
- 响应式规范从架构层根治"压扁"，并用固定验收视口（1280×720 / 1536×864）防回归。
**负面 / 待偿**
- 85 个文件需按域重写，是一次中等规模迁移（管理后台 8–15 页量级，AI 辅助约 2–3 周，见成本模型）。
- `recharts`（React-only）需换代，图表栈待定（OPEN-DECISIONS OD-02）。
- 刻意不采用 npm latest 的大版本（vue-router 5.3.1 / pinia 4.0.3 / vite 8.3.0），技术债为"滞后一个大版本"，换取与既有工程一致（OD-01 跟踪）。
**风险缓解**
- 首次发布前先归档 React 产物为回滚点；发布窗口内保留可立即回滚的符号链接。
- 类型检查（`vue-tsc`）与构建作为必过门，拦截幻觉依赖与静默失效。
