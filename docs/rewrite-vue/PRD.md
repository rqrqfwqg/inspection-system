## 0. 一句话目标
在**不改后端、不改 API、不新增后端能力**的前提下，把现有 React 19 前端整站重写为 Vue 3.5 + Element Plus 2.9，并**彻底修复"1920×1080 + 系统缩放 125%/150% 下元素拉伸变扁"的适配缺陷**，与 `tools-management/vue-frontend` 前端栈统一。

---

## 1. 问题陈述

**谁**：广州白云机场 T3 GTC 交通中心项目管理部运维人员（现场运维 1 人 + 管理部办公室若干人）。

**什么场景**：在 1920×1080 显示器、Windows 系统缩放 125%/150%（CSS 视口实际仅约 **1536×864 / 1280×720**）下访问 `https://<OPS_HOST>/ops/`。

**什么痛点**：元素被**拉伸变扁/压扁**，卡片、表格、图表错位，可用视口被压缩后布局撑破。

**现在怎么解决**：无解。现有前端用 Tailwind **固定像素**写死外壳（`MainLayout` 用 `h-screen`，`Header` 用 `h-16`，`Sidebar` 固定 `w-64`，内容区 `p-4/p-6`），元素尺寸不随 DPI 缩放自适应，缩放后容器高度被压扁、宽度溢出。

**为什么不行**：固定 px 不等于物理像素；系统缩放改变 `devicePixelRatio` 却不改 CSS px 语义，写死的 px 高度/宽度在缩放下必然挤压或溢出。用户同时要求技术栈统一到 Element Plus（另一项目已用该栈），因此本次为整站重写而非局部修补。

## 4. 我们的差异化

- 不是通用 CMMS，而是**单一站点（T3 GTC GTC 交通中心）的资产"家底"系统**：楼栋/房间/设备/子系统/BA 五维强关联，检索即联动的纵深是通用产品给不了的。
- **"搜索即导航"**：任一编号可在数据表、台账、可视化、扫码四端互相跳转（现有 `?code=` 深链已实现）。
- **不引入后端新能力**，因此**不做 Maximo 式的功能堆叠**：聚焦"看见、找准、导出、打印、扫码"五个真动作。
- **适配是本次重写的核心卖点**：小程序诉求（少示屏变形）→ 交付"任意系统缩放 100%/125%/150% 不变形"的硬承诺（竞品普遍在此翻车）。

## 9. 验收标准（Given / When / Then）

- Given 1920×1080 + 系统缩放 **125%**（视口约 1536×864），When 打开 `/ops/dashboard`，Then 无横向滚动条、卡片不拉伸、元素不重叠。
- Given 同上条件切换 **150%**（视口约 1280×720），When 浏览任意 13 路由，Then 布局不撑破、关键操作按钮仍可见可点。
- Given 同一页面在 **100%/125%/150%** 三种缩放下，When 依次截图对比，Then 无"拉伸变扁"、无元素重叠、无内容溢出（相对布局比例一致）。
- Given 资产总台账（约 8977 条），When 打开 `/asset/devices`，Then 首屏 ≤3s，支持分页/筛选/排序，125% 缩放下表头与列不错位。
- Given 用户从可视化 `?tab=area&code=XXX` 打开详情抽屉，When 点击浏览器后退，Then 正确回到上一视图状态（**不得出现 Maximo 式退不回去**）。
- Given 运维人员点击二维码标签"打印"，When 触发打印，Then 输出 A4 横向、标签不跨页断裂（与现样式一致）。
- Given 21 张动态表任一，When 新增/编辑/删除字段与记录并跨表转移，Then 数据正确落库且其他视图同步。

## 10. 边界条件

- **空状态**：无记录/无搜索结果 → Element Plus `el-empty` + 明确下一步引导文案（禁止空洞占位）。
- **错误状态**：API 失败（422 数组 detail / 5xx）→ 全局 toast 展示可读错误，不白屏（沿用现有 detail 解析逻辑）。
- **加载状态**：大表格用 `v-loading` / 骨架屏；树懒加载显示 loading 节点。
- **边界值**：0 条 / 1 条 / 最大分页；871 房间树与 8977 台账不得一次性全渲染。
- **并发**：多标签页编辑同一记录 → 以最后写入为准，前端提示冲突。
- **离线**：扫码盘点场景支持本地暂存、联网补传（现场可能弱网）。
- **权限拒绝**：`adminOnly` 菜单（用户管理/资料配置）对非管理员隐藏，直连路由需兜底拦截。

| 可访问性 | WCAG 2.1 AA 基本合规（键盘可达 + 对比度） | P2 |
| 国际化 | 预留 i18n 接口（本期不做） | P2 |
| 数据埋点 | 核心流程埋点（见 §12） | P1 |
| 图标方案 | **统一 SVG 图标库**（Element Plus 生态图标，具体由架构师锁定）；文档一律以文字描述图标（如"文件搜索图标"），**禁用 emoji 作功能图标** | P0 |

---

## 12. 数据埋点方案

前端轻量封装 `trackEvent()`，事件命名 `{对象}_{动作}`，属性含 `user_id / timestamp / device / version`，**额外必带 `viewport_width` 与 `devicePixelRatio`**（用于验证缩放适配是否真的生效）：

| 类别 | 必埋事件 | 说明 |
|------|----------|------|
| 获客/进入 | `page_view` | 路由级 PV（含 `viewport_width`、`devicePixelRatio`） |
| 激活 | `asset_ledger_searched` | 首个核心动作：检索/筛选台账 |
| 激活 | `device_detail_opened` | 打开设备详情抽屉（含来源路由） |
| 留存 | `session_start` / `session_duration` | DAU/MAU、频次 |
| 转化 | `qr_label_printed` / `inventory_scan_done` | 打印与扫码完成 |
| 异常 | `error_occurred` | 前端错误 + API 错误（含 status） |
| 适配 | `layout_overflow_detected` | 检测到横向溢出/元素重叠时上报（自证适配体检） |

不采集隐私数据（不上报 IP、不存原始输入内容）。

## 附：重写最容易翻车的 6 个点（来自竞品差评）

1. **缩放适配**（本项目的立项理由）——px 写死必翻车，见 §1/§11。
2. **深链与浏览器后退**——Maximo 差评明确"后退键失效"；`?tab=`/`?code=`/`/:tableId` 必须进 History。
3. **大表格性能**——Maximo/Fiix 均被批"大数据量变慢"；8977 条必须分页 + 列宽自适应。
4. **移动/弱网扫码同步**——Fiix/eMaint 最高频差评是"移动端同步问题"；扫码盘点需离线暂存。
5. **打印样式**——二维码 A4 横向 `@media print` 易在重写中丢失。
6. **树形大数据量**——871 房间 + 层级设备一次性渲染会卡死，必须懒加载。
